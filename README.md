# PVT-Simulator (Black Oil)

Простой PVT-симулятор Black Oil модели на классических корреляциях
(Standing, Vasquez-Beggs, Beggs-Robinson, Dranchuk-Abou-Kassem, Lee-Gonzalez-Eakin,
McCain, Wichert-Aziz).

## Структура проекта

- `units.py` — конвертация единиц измерения (метрика Казахстан <-> field units США),
  включая МПа (частая единица давления в казахстанских PVT-отчётах)
- `pvt_correlations.py` — сами корреляции, всегда считают во внутренних field units
  (psi, °F, scf/stb) — это стандарт для этих корреляций
- `app.py` — Streamlit UI PVT-калькулятора, конвертирует ввод/вывод в выбранную
  систему единиц
- `field_data.py` — разбор "сырых" лабораторных PVT-таблиц по месторождению:
  многострочные шапки, гибкое сопоставление колонок по ключевым словам,
  очистка "грязных" значений, нормализация кодов горизонтов, регрессия
  для линий тренда, QC-проверки (аномальные пробы, материальный баланс
  Rs(м3/т) vs Rs(м3/м3), давление отбора ниже Pb)
- `tests/` — автотесты (pytest) на корреляции, конвертацию единиц и парсер
  полевых данных; гоняются автоматически на каждый push через GitHub Actions
  (`.github/workflows/tests.yml`)
- `pages/1_Анализ_месторождения.py` — вторая страница приложения: загрузка
  таблицы отборов проб и построение зависимостей (Rs vs Pb, Bo vs Pb,
  вязкость vs Pb, свойство vs глубина и т.д.) по всему массиву или с
  группировкой по горизонту/блоку/скважине — работает и без колонки горизонта
- `pvt_tuning.py` — калибровка (tuning) корреляций Standing/Beggs-Robinson под
  фактические лабораторные данные: находит мультипликативные коэффициенты
  для Pb/Bo/μo методом наименьших квадратов, коэффициенты можно сохранить на
  странице «Анализ месторождения» и применить на главной странице-калькуляторе

## Запуск

```bash
pip install -r requirements.txt
streamlit run app.py
```

Откроется браузер на `http://localhost:8501`.

## Проверка

- Полный набор автотестов: `pip install -r requirements-dev.txt && pytest tests/ -v`
  (73+ теста на корреляции, конвертацию единиц и парсер полевых данных)
- Тесты конвертации единиц: `python units.py` (должно вывести "все self-тесты пройдены успешно")
- В UI: слева выберите систему единиц ("Метрическая" или "Field units") — все поля
  ввода, таблица и подписи графиков должны пересчитаться и переименоваться
- Введите плотность нефти в кг/м³ — рядом появится справочное значение в °API
  (и наоборот при переключении в field units)
- На графиках отмечена вертикальная линия давления насыщения Pb
- Внизу страницы можно скачать таблицу в CSV или Excel и загрузить лабораторные
  PVT-данные для визуального сравнения с расчётными кривыми

## Диапазоны применимости корреляций

Каждая функция в `pvt_correlations.py` содержит в docstring диапазон
применимости в field units и его аналог в метрических единицах.
UI показывает предупреждения, если введённые параметры выходят за эти диапазоны.

## Анализ лабораторных данных по месторождению (страница «Анализ месторождения»)

Отдельная страница для загрузки "сырой" таблицы лабораторных отборов проб
(много скважин/горизонтов/блоков) и построения зависимостей между свойствами.

Как проверить:
1. `streamlit run app.py`, слева в навигации выбрать страницу
   «Анализ месторождения»
2. Загрузить xlsx/csv с таблицей отборов — программа сама предложит, с какой
   строки начинается шапка и данные (можно поправить), и предложит
   сопоставление колонок со стандартными полями (Горизонт, Pb, Rs, Bo,
   вязкость, глубина и т.д.) — тоже можно поправить руками
3. Строки-агрегаты вида «Среднее значение: горизонт …» определяются
   автоматически и по умолчанию исключаются из анализа
4. Коды горизонтов нормализуются (например, "PT-IV" и "РТ-IV", написанные
   разными алфавитами, будут считаться одним горизонтом)
5. В разделе «Зависимости» выбрать X/Y (например, Pb и Rs) и группировку
   (без группировки / по горизонту / по блоку / по скважине) — строится
   график рассеяния с линией тренда (линейной или степенной) и R² по каждой
   группе или по всему массиву целиком
6. Если в данных нет колонки горизонта/блока — соответствующие фильтры и
   группировки просто не показываются, всё остальное работает как обычно

## Калибровка корреляций под факт (tuning)

В разделе «6. Калибровка корреляций Standing под факт» на странице
«Анализ месторождения»:
1. Задайте плотность нефти (кг/м³) и γg газа — это вход для модели Standing
   (в лабораторной таблице обычно нет отдельно измеренной плотности товарной
   нефти, поэтому это ваше лучшее приближение, не автоматика)
2. Выберите — считать коэффициенты по всему массиву или по каждой группе
   (например, по каждому горизонту) отдельно
3. Программа для каждой пробы считает, что предсказала бы корреляция Standing
   (по её же Rsb и T), сравнивает с фактом и подбирает коэффициент методом
   наименьших квадратов — с метриками MAPE и R² до/после калибровки
4. Кнопка «Сохранить калибровку и использовать в калькуляторе» передаёт
   коэффициенты на главную страницу через `st.session_state` — там поверх
   стандартной кривой Standing появляется откалиброванная (пунктиром), с
   пометкой, по какому горизонту и на скольки пробах она посчитана
5. Как проверить: на реальных полевых данных типичная картина — Bo у
   Standing и так неплохо садится под факт (коэффициент ~1.0-1.05), а вот Pb
   и особенно вязкость обычно требуют заметной калибровки (это нормально,
   вязкость — исторически самое неточное свойство у корреляций)

## Контроль качества данных (QC)

На странице «Анализ месторождения», в разделе «3. Единицы давления и
очистка данных»:
1. **Аномальные пробы** — если в номере скважины/пробы встречается звёздочка
   (`31*`, `25*` — типичное обозначение "непредставительного" замера),
   программа находит такие строки и по умолчанию исключает их из анализа
   (галочку можно снять)
2. **Материальный баланс Rs(м³/т) ↔ Rs(м³/м³)** — если в отчёте есть обе
   единицы газосодержания для одной пробы, программа выводит плотность
   товарной нефти из баланса массы (`ρ_пласт·Bo = ρ_товарная + Rs·γg·ρ_воздух`)
   и проверяет, согласуются ли обе единицы Rs между собой для этой же
   пробы. Расхождение больше 5% выводится отдельным списком — обычно это
   означает опечатку при вводе одной из двух величин. Проверка требует
   колонку относительной плотности газа (γg после однократного
   разгазирования) — без неё честно помечается как "нет данных", а не
   выдаёт вводящую в заблуждение цифру
3. **Давление отбора ниже Pb** — если пробу отбирали при давлении ниже
   давления насыщения, в пласте уже мог идти двухфазный поток; такие
   строки не исключаются, но подсвечиваются для внимания инженера

Как проверить: на демонстрационных тестовых данных (`tests/test_field_data.py`,
класс `TestBuildCleanDataframe`) есть примеры и согласованной, и намеренно
испорченной пробы — второй должен показать расхождение >50%, первый — <1%.

## Кислый газ: коррекция Wichert-Aziz (H2S, CO2)

На главной странице, в разворачивающемся блоке сайдбара «Кислый газ H2S/CO2
(коррекция Wichert-Aziz)» — вводится мольный состав H2S и CO2 в газе (по
умолчанию 0%, т.е. обычный "сладкий" газ, поправка не применяется).

Зачем нужна: у месторождений с высоким содержанием H2S/CO2 (Тенгиз,
Королёвское, Карачаганак и т.п.) без этой поправки Z-фактор, Bg и вязкость
газа считаются некорректно — псевдокритические давление/температура,
рассчитанные для "чистого" газа (Standing), нужно сдвинуть по корреляции
Wichert-Aziz (1972) ПЕРЕД расчётом Z-фактора (DAK).

Как проверить: на реальных данных Королёвского месторождения (H2S≈14.4 мол.%,
CO2≈3.19 мол.%, `tests/test_pvt_correlations.py`, класс `TestWichertAziz`) —
критическая температура снижается примерно на 6%, критическое давление — на
7%, а Z-фактор при пластовых условиях (~3660 psi, ~73°C) меняется больше чем
на 2% — это не шум, а реальная и материальная поправка для сернистых
месторождений. При H2S=CO2=0 поправка тождественно равна нулю.
